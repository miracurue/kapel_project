# Clinical Compass

Демонстрационный MVP поддержки психиатра и пациента при тревожно-депрессивной
симптоматике. Это прототип поддержки решений, а не диагностическая или лечебная
система. В демо используются только синтетические данные.

## Локальный запуск

Требуются Node.js 26 и npm. Скопируйте `.env.example` в `.env`, заполните
пустые ключи случайными значениями и выполните:

```bash
npm ci
npm run migrate
npm run seed
npm start
```

Приложение откроется на `http://127.0.0.1:3000`. В демо-режиме на стартовой
странице доступны кнопки входа по ролям. Локальная почта через Docker доступна
на `http://127.0.0.1:8025`.

```bash
docker compose -f deploy/compose.dev.yml up --build
```

## Показ

```bash
bash scripts/demo-up.sh   # свежая синтетическая база + насыщенные данные, http://127.0.0.1:3000
```

На главной — «Войти как» пациент, психиатр, психолог, администратор, ведущий; у «Ведущего» — маршрут показа.
Ответы ИИ в демо — заглушка (`AI_DEMO_REPLIES=1`). Если в `.env` задан `GIGACHAT_AUTH_KEY` (ключ авторизации Сбера), `scripts/demo-up.sh` включает GigaChat на синтетических данных; без ключа работает заглушка.

## Проверки

```bash
npm run ci
npm run test:gate -- --upto В3 --kind all
npm run test:regression
```

API описан в `docs/openapi.yaml`.

Данные SQLite, загрузки и `.env` не должны попадать в Git. Настоящие данные
пациентов использовать в демо запрещено.

## Веха В2: лечение и тесты

Пациент может пройти назначенный или самостоятельный STAND-IN опросник, вести
дневник и отметить купленный препарат/приём. Психиатр работает со списком и
карточкой закреплённого пациента, создаёт черновик плана по МНН и назначает
опросники. Внесённые пациентом лекарства требуют просмотра специалистом;
психолог не получает доступ к разделу лечения.

Каталог МНН, торговые наименования, шкалы, результаты распознавания бланка и
тексты поддержки курса — синтетические STAND-IN данные. Они не являются
назначением, диагнозом, проверкой дозировок или клинической рекомендацией и
требуют ревью Clinical Lead до любого не-демо использования.

## Веха В3: сигналы и связь

Пациент может безопасно прикрепить файл, отправить сообщение специалисту,
сообщить о нежелательном явлении и заполнить анкету перед приёмом. Каждый
свободный ввод проходит кризисный шлюз до согласий и будущего ИИ; путь помощи
с номером 112 остаётся доступен при отказе записи сигнала.

Психиатр и психолог видят кризисные сигналы закреплённых пациентов и атомарно
берут их в работу; НЯ доступны только психиатру. Извещение о НЯ формируется
только как STAND-IN-черновик и никогда не отправляется автоматически. Загрузки
хранятся в `DATA_DIR/files` вне `public`; для демо обязателен
`FILE_SCANNER=none`, а режим `clamd` закрывает загрузку до подключения сканера.

JPEG и PNG декодируются и пересохраняются через `sharp` без метаданных;
повреждённые изображения отклоняются. Врач скачивает вложение только после
отправки и окна отмены, пока у него есть доступ к соответствующей переписке.
Пациент выбирает адресата из своих специалистов; тексты и файлы переписки
доступны её участникам и подтверждённому замещающему.

При отзыве обязательного согласия обычные записи блокируются, а кризисный
ввод возвращает карточку помощи с `saved: false`. Резервный специалист получает
доступ только к переданному ему кризисному сигналу. Отмена действий с сигналом
восстанавливает его состояние; клинические заметки сохраняются в клинической
записи и не копируются в служебные журналы.

## Сервис ml-worker: речь, OCR, имена (В4)

`ml-worker/` — отдельный Python-сервис (FastAPI, порт 8000) с локальными
моделями: расшифровка речи GigaAM-v3 + silero-vad (`POST /stt`), распознавание
сканов и фото Tesseract `rus+eng` (`POST /ocr`), выделение имён и телефонов
Natasha (`POST /ner`), состояние (`GET /health`). Он работает только во
внутренней сети Docker и требует общий токен `ML_WORKER_TOKEN` из `.env`.

Запуск в разработке:

```bash
python3 ml-worker/fetch_models.py --check   # проверить наличие моделей
python3 ml-worker/fetch_models.py           # скачать модели по models.lock.json
docker compose -f deploy/compose.dev.yml --profile ml up --build ml-worker
```

Без Docker сервис можно запустить напрямую (тоже без доступа в интернет,
модели уже должны лежать в `ml-worker/models`):

```bash
python3 -m pip install --require-hashes -r ml-worker/requirements.lock
ML_WORKER_TOKEN=... ML_WORKER_MODELS_DIR=ml-worker/models \
  python3 -m uvicorn app:app --app-dir ml-worker --host 127.0.0.1 --port 8000
```

Файлы моделей в Git не попадают (`ml-worker/models/` игнорируется) и
монтируются в контейнер только для чтения; sha256 закреплён в
`ml-worker/models.lock.json`. Код модели GigaAM (`modeling_gigaam.py`)
исполняется при загрузке (`trust_remote_code`): включать `/stt` можно только
после его просмотра разработчиком. Если моделей нет, `/stt` и `/ner`
отвечают 503 — приложение продолжает работать по правилам.

## Методики ГТР в демо

Во вкладке специалиста «Тесты» есть карточки Г1–Г16. Г2–Г7 доступны для назначения
(ИТТ — две формы), HARS — справка, Г8–Г16 — «Скоро появится».
Прямая ссылка: `/work?tab=tools&tool=bai` (или другой код).
Результаты пациенту заменены ободряющим сообщением и подсказкой обсудить их
с назначившим специалистом. Подсчёт и тексты требуют клинического ревью.
Проверки: `node --test --test-concurrency=1 tests/regression/gad_methods_workflow.test.js tests/regression/gad_methods_browser.test.js`.


Объединённый дневник пациента (`/app?tab=diary`) повторяет утверждённый
`diary-demo.html`: самочувствие, сон, план лекарств, привычки, календарь и
заметки. Данные сохраняются в SQLite через `/api/v1/me/diary-workspace`
(миграция 0023), приёмы — в `med_log`. Старые записи дневника сохраняются;
прошлые дни доступны для чтения, исправления — через специалиста.
Настройки напоминаний сохраняются; новая рассылка этим изменением не запускается.
